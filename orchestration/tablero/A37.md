## Por qué

Emilio, hoy, con estas palabras: *"el sistema corre en la web, no abre terminales, si no es
insostenible"*. Y antes, dos veces: *"eso es una app que vive en una web, un sistema independiente, no
depende de Windows"*.

Hoy no es así, y lo he medido. **La aplicación está corriendo en el servidor de Oracle pero no está
publicada en ninguna URL.**

Lo que sí está en marcha allí:

```
$ ssh oracle-vps "systemctl list-units --state=running | grep ultrarentable"
ultrarentable-api.service          active running   Ultrarentable FastAPI Backend Service
ultrarentable-discovery.service    active running   Pipeline 24/7 de descubrimiento
ultrarentable-backfill-40.service  active running   Descarga de Russell 2000 y bono 30a

$ ss -tlnp | grep -E ':(3000|8000)'
0.0.0.0:3000   next-server (v1…)        <- la web, viva
0.0.0.0:8000   python                   <- la API, viva
```

Y lo que **no** está: nginx no la sirve. Sus tres sitios publicados son de otras cosas, y la raíz
del puerto 80 se va a otro producto:

```
$ ls /etc/nginx/sites-enabled/
9router.sslip.io    freellmapi.co    pro

$ curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1/     ->  307
$ curl -s http://127.0.0.1/ | head -c 200                      ->  /dashboard      (no es Ultrarentable)

$ grep -rn 'server_name' /etc/nginx/ | grep -i ultrarentable   ->  (nada)
```

Consecuencia práctica, y es la que Emilio nota: **la única forma de ver la aplicación es levantarla
en su PC con un script de PowerShell y mirarla en `localhost`**. Eso es justo lo que él llama
insostenible, y con razón: su PC se apaga, y mientras esté así la web no existe para nadie más que
para él y solo cuando está delante.

## Qué hacer

1. **Publicar la web del servidor en una URL.** Ya hay un patrón de nombre en uso en esa máquina
   (`143-47-35-167.sslip.io`, que resuelve la IP sin necesidad de comprar dominio), así que crea un
   sitio de nginx propio para Ultrarentable —**sin tocar los tres que ya existen**— que sirva:
   - la web (`next-server` de `127.0.0.1:3000`) en la raíz de ese nombre,
   - la API (`127.0.0.1:8000`) bajo `/api/`,
   - con `proxy_set_header Host`, `X-Forwarded-For` y `X-Forwarded-Proto`, y soporte de WebSocket
     (`Upgrade`/`Connection`) porque Next lo usa.
2. **Comprobar que el servicio de la web es un servicio de verdad**, con `Restart=always` y
   `enable`, igual que la API. Si el `next-server` de `:3000` está corriendo a mano (sin unidad de
   `systemd`), créale la unidad: hoy no sobreviviría a un reinicio y eso incumple la regla de que
   todo resucita solo.
3. **Decir en el parte la URL exacta** que Emilio tiene que abrir. Es el entregable de esta tarea:
   una dirección que él pega en el navegador y ve la aplicación, sin `localhost` y sin scripts.
4. **No apagues la instancia local del PC.** Sigue siendo útil para ver un cambio mientras se
   programa; lo que cambia es que deja de ser la única.

## Aceptación

```bash
# 1) la web contesta por su nombre publico, desde el propio servidor
ssh oracle-vps "curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: <NOMBRE ELEGIDO>' http://127.0.0.1/"        # 200
ssh oracle-vps "curl -s -H 'Host: <NOMBRE ELEGIDO>' http://127.0.0.1/ | grep -c Ultrarentable"                  # > 0

# 2) la API contesta bajo /api/
ssh oracle-vps "curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: <NOMBRE>' http://127.0.0.1/api/v2/system/vigia-local"   # 200 o 404 con JSON, no 502

# 3) los tres sitios que ya existian siguen en pie
ssh oracle-vps "nginx -t; curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/"                          # sin errores, y el 307 de antes

# 4) la web es un servicio que resucita
ssh oracle-vps "systemctl is-enabled <unidad-de-la-web>; systemctl show <unidad> -p Restart"                     # enabled, Restart=always
```

## Prohibido

Tocar, mover o desactivar los sitios `9router.sslip.io`, `freellmapi.co` y `pro`: son de otros
productos de Emilio y tienen que seguir funcionando igual. Comprar ni registrar dominios. Abrir
puertos nuevos al exterior más allá del 80/443 que ya están. Parar `ultrarentable-api`,
`ultrarentable-discovery` ni `ultrarentable-backfill-40`.

## Qué se verá en la web al terminar

Lo más importante que se puede ver: **la web entera, en una dirección**. Hoy, para ver el trabajo de
todo el día hay que estar en el PC de Emilio con un script levantado. Al terminar esta tarea hay una
URL que él abre desde cualquier sitio y ve `/sistema`, `/plan` y `/estrategias/candidatos` con los
datos del servidor.
