## Por qué

Emilio ha abierto la web y ha escrito: *"había un montón de estrategias cuando entrabas en la página
de generación... y ahora no hay nada. Luego en candidatas también había un montón de estrategias con
unos porcentajes decentes para empezar, y ahora no sale nada de nada de nada"*.

**No se han perdido las estrategias. Se ha muerto la API y nadie la ha levantado.** Medido:

```
netstat        :3100 escuchando (PID 25848) · :8100 NADA
api_err.log    ultima linea 22:07:59 -> "Uvicorn running on http://127.0.0.1:8100"
               y despues NADA: no hay traza de error, o sea que no se cayo sola, la mataron
watchdog.log   ultimo latido 19:06:04  <-- el vigia murio TRES HORAS ANTES que la API
schtasks       ninguna tarea programada de ultrarentable
Get-Service    ningun servicio de ultrarentable
censo en disco 94 MB, intacto, fecha 03/09 22:07  <-- los datos estan todos
```

**La causa de fondo no es que la API muriera, es que el vigía era un bucle a mano y también murió.**
Un bucle que vigila a otro proceso no vale: cuando se cierra su consola o su padre, se va con él y
deja de avisar en silencio. Lo que no puede morir es una **tarea programada oculta que se ejecuta,
comprueba y sale**.

**Y hay un segundo fallo, más grave para Emilio.** Con la API muerta, las páginas devuelven **200 OK
y una tabla vacía, sin un solo aviso**:

```
/estrategias/generacion    200  42.261 bytes   0 filas   0 avisos
/estrategias/mejora        200  44.712 bytes   0 filas   0 avisos
/estrategias               200  41.564 bytes   0 filas   0 avisos
/estrategias/verificadas   200  37.678 bytes   0 filas   0 avisos
```

Es decir: **la web le dijo a Emilio que no hay estrategias cuando lo que pasaba es que no podía
preguntarlo.** Eso es peor que un error, porque parece un dato. Cero estrategias y "no puedo
consultarlas" tienen que verse distinto en pantalla.

## Qué hacer

**1. Levanta la API** en el 8100, oculta, como ya estaba.

**2. Ponla bajo un supervisor que no pueda morirse con nadie.** Una **tarea programada de Windows,
oculta** (`-WindowStyle Hidden`, la tarea en modo Hidden), con **dos disparadores**: al iniciar
sesión y **repetida cada 2 minutos**. Lo que ejecuta hace **una pasada y sale**: comprueba
`:8100/health` y `:3100`, y si alguno no responde lo relanza oculto y lo escribe en
`orchestration/site/watchdog.log` con la hora y qué relanzó. **Nada de bucles infinitos lanzados a
mano, que es justo lo que ha fallado hoy.**

**3. Ni una consola visible.** Ni al arrancar, ni cada 2 minutos, ni al relanzar. Si al probarlo
parpadea una ventana en el escritorio de Emilio, está mal hecho. Es la directiva de siempre.

**4. Que la web diga la verdad cuando no hay fuente.** Si la consulta a la API falla, la página no
puede enseñar una tabla vacía: enseña una banda gris con **"sin conexión con el motor · reintentando"**
y la hora del último dato bueno. Cero de verdad se escribe "0 estrategias"; no poder preguntarlo se
escribe distinto. En gris, negro y blanco, sin colorines.

**5. Con la API ya viva, vuelve a medir las cuatro páginas y pon los números en el parte**: filas que
salen en generación, en candidatas, en mejora y en verificadas. Si alguna sigue vacía **con la API
viva**, eso es otro problema y lo dices en el parte como HALLAZGO; no lo arregles aquí.

## Aceptación

```powershell
# 1) la API responde
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:8100/health         # 200

# 2) EL SUPERVISOR EXISTE (esto no podia pasar con el codigo de ayer)
schtasks /query /tn "Ultrarentable-Vigia" /v /fo list | findstr /i "Estado Repetir Oculto"

# 3) LA PRUEBA DE VERDAD: matar la API y NO tocar nada
Stop-Process -Id (Get-NetTCPConnection -LocalPort 8100).OwningProcess -Force
#    esperar 3 minutos sin hacer nada y volver a preguntar:
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:8100/health         # 200 otra vez
Get-Content orchestration\site\watchdog.log -Tail 5                   # tiene que decir que la relanzo

# 4) la web avisa en vez de mentir: con la API parada, la pagina lo dice
curl -s http://127.0.0.1:3100/estrategias/generacion | findstr /i "sin conexion"

# 5) y con la API viva, los numeros
curl -s "http://127.0.0.1:8100/api/v2/candidatos?limit=1" | head -c 200
```

En el parte pega **las cinco salidas**, sobre todo la 3: el minuto en que la mataste, el minuto en que
volvió sola y las líneas del log.

## Prohibido

Un bucle `while` lanzado a mano como supervisor (es lo que ha fallado). Cualquier ventana o consola
visible. Dar por bueno "la he arrancado" sin la prueba 3, que es la única que demuestra que se
resucita sola. Tocar el censo ni los datos: están intactos y el problema no está ahí. Barra de menú
arriba; grises, negro y blanco.

## Qué se verá en la web al terminar

Que **vuelven a salir las estrategias** en generación y en candidatas, que es lo que Emilio ha echado
en falta. Y que si el motor vuelve a caerse, la pantalla lo dice con todas las letras en vez de
enseñar una tabla vacía que parece decir "no hay nada".
