```bash
#!/usr/bin/env bash
# ARNÉS ANTIGRAVITY — pre-commit
# Regla: SOLO el orquestador commitea (ORQ_COMMIT=1). Los agentes de ejecución (AGY) trabajan en
# ramas agy/* dentro de su propio worktree, dejan el working tree listo y escriben DONE. Nunca commitean.
# Activar una vez por repo (lo hace el orquestador):  git config core.hooksPath .githooks
set -u
branch="$(git rev-parse --abbrev-ref HEAD 2>/dev/null || echo desconocida)"

# REGLA INVERTIDA (2026-09-02, tras el fallo del agente SMOKE): antes se BLOQUEABA por lista
# negra (rama agy/* o AGY_AGENT definido) y las dos guardas resultaron MUERTAS en el montaje
# real: Orca crea las ramas con el namespace del usuario ('JOSFER78/agy-SMOKE', que no casa con
# 'agy/*') y no propaga AGY_AGENT al entorno del worker. Un agente commiteó de verdad.
# Ahora es lista BLANCA: NADIE commitea salvo el orquestador con ORQ_COMMIT=1, sea cual sea la
# rama, el usuario o las variables de entorno. No depende de cómo se llame nada.
if [[ "${ORQ_COMMIT:-}" != "1" ]]; then
  echo "[ARNÉS] commit BLOQUEADO en '$branch': solo el orquestador commitea (ORQ_COMMIT=1)." >&2
  echo "[ARNÉS] Si eres un agente: deja el working tree como está y escribe DONE_<ID>.md." >&2
  exit 1
fi

# Nunca datasets pesados al índice (manifiestos sí).
if git diff --cached --name-only | grep -E '^data/(normalized|raw|sqx_imports)/' | grep -Ev '(manifest|MANIFEST|\.md$)' | grep -E '\.(json|csv|parquet|bi5|zip)$' >/dev/null 2>&1; then
  echo "[ARNÉS] commit BLOQUEADO: hay datasets pesados en el índice (data/normalized|raw|sqx_imports). Solo manifiestos." >&2
  exit 1
fi

# Nunca 'rm' de ficheros versionados sin pasar por cuarentena: un borrado (D) exige un MANIFEST en cuarentena/ en el mismo commit.
if git diff --cached --name-status | grep -E '^D\s' >/dev/null 2>&1; then
  if ! git diff --cached --name-only | grep -E '^cuarentena/.*MANIFEST' >/dev/null 2>&1; then
    echo "[ARNÉS] commit BLOQUEADO: borras ficheros sin manifiesto en cuarentena/ (regla: nunca rm; se aparca con MANIFEST SHA-256)." >&2
    exit 1
  fi
fi
exit 0
```

#### `C:/Users/yo/.orq-hooks/pre-push`
```bash
#!/usr/bin/env bash
# ARNÉS ANTIGRAVITY — pre-push
# Regla: push SOLO del orquestador (ORQ_PUSH=1) y NUNCA de ramas agy/*. Un agente AGY no puede
# publicar nada aunque lo intente: el hook lo corta antes de salir de la máquina.
set -u
if [[ "${ORQ_PUSH:-}" != "1" ]]; then
  echo "[ARNÉS] push BLOQUEADO: solo el orquestador puede publicar (ORQ_PUSH=1), tras auditar el lote." >&2
  exit 1
fi
# Las ramas de agente NUNCA se publican. Ojo al nombre real: Orca crea la rama con el namespace
# del usuario ('JOSFER78/agy-SMOKE'), así que el patrón 'refs/heads/agy/*' NO casaba y el push
# pasaba (fallo detectado el 2026-09-02 con el agente SMOKE). Se casa 'agy' en cualquier posición.
while read -r local_ref local_sha remote_ref remote_sha; do
  case "$local_ref" in
    *agy/*|*agy-*|*AGY/*|*AGY-*)
      echo "[ARNÉS] push BLOQUEADO: la rama '$local_ref' es de un agente de ejecución; se integra a main por el orquestador, no se publica." >&2
      exit 1 ;;
  esac
done
exit 0
```

## §3 Hallazgos

1. **Intento c (`git -c core.hooksPath=/dev/null`) y d (`git commit --no-verify`)**:
   - Son mecanismos nativos de Git en cliente. Ningún hook local puede impedir que un proceso local con acceso a git use `-c core.hooksPath` o `--no-verify`.
   - *Mitigación*: La defensa real recae en la verificación externa del orquestador (`scripts/aceptar_agy.py`), que audita que no existan commits creados por el agente sobre `BASE` antes de cualquier integración.

2. **Intento j (`ORQ_COMMIT=1`)**:
   - La lista blanca del hook `pre-commit` depende de una variable de entorno (`ORQ_COMMIT=1`). Cualquier agente que lea el hook o conozca la convención puede definir dicha variable en su subproceso y hacer commit localmente.
   - *Propuesta de Cierre*: La soberanía reside en el orquestador: el orquestador valida que `git log BASE..HEAD` sea estrictamente 0 en el worktree del worker antes de integrar.

3. **Sub-intento k5 (Integridad del GO en `scripts/aceptar_agy.py`)**:
   - `scripts/aceptar_agy.py` lee `orchestration/agy/GO_<ID>.md` desde el árbol de trabajo local del agente (`worktree / "orchestration" / "agy" / f"GO_{agent_id}.md"`).
   - Si un agente edita su propio archivo `GO` e inserta rutas bajo `## TERRITORIO` o declara `Toca semántica del motor: SÍ`, `aceptar_agy.py` asume que esas rutas son legítimas y no detecta la violación de territorio ni la regla #26.
   - *Propuesta de Cierre*: `aceptar_agy.py` debe leer el `GO` original desde el commit BASE del orquestador (`git show BASE:orchestration/agy/GO_<ID>.md`) o comparar el sha256 del `GO` del worktree contra el blob de `BASE` antes de evaluar el territorio.

4. **Codificación de salida en Windows (`scripts/aceptar_agy.py`)**:
   - En Windows, `subprocess.run(..., text=True)` utiliza `cp1252` por defecto. Al ejecutar `git diff` sobre ficheros con acentos o UTF-8 (como los comentarios en español de los `GO`), se producía un `UnicodeDecodeError` que abortaba el arnés con error interno si no se especificaba `encoding="utf-8"` en `subprocess.run` o `PYTHONUTF8=1`.
   - *Recomendación*: Añadir `encoding="utf-8", errors="replace"` a las llamadas `subprocess.run` en `scripts/aceptar_agy.py`.
