## Decisiones tomadas

1. **El README ya no es un archivo técnico de instalación** — es la guía de entrada para cualquier IA o persona.
2. **ESTADO.md es el archivo de referencia rápida** — se actualiza al final de cada sesión.
3. **La bitácora registra el historial** — una entrada por fecha de sesión.
4. **Las 24 estrategias viejas se descartan** como candidatas kamikaze — no cumplen el scorecard.
5. **La búsqueda debe cambiar a fitness por retorno puro** (no Sharpe/PF) para el modo kamikaze.

---

## Descubrimientos clave

- **Ningún candidato se acerca a miles de %** — el sistema genera estrategias, pero con la configuración actual (fitness por Sharpe/PF) los retornos son muy bajos para el modo kamikaze.
- **El universo de indicadores está limitado** — hay que ampliarlo para dar más opciones al algoritmo genético.
- **SQX funciona y genera** — el problema no es el motor sino la configuración de búsqueda.

### Diagnóstico de cabecera (evidencia real del `project.cfx`)
Se extrajo la configuración REAL del proyecto `Ultra_Auto_Pilot` (`Build-Task1.xml`) y se confirmaron
**5 errores de causa raíz** que explican el bajo rendimiento:

| # | Error real (evidencia XML) | Impacto |
|---|---|---|
| 1 | Fitness = `NetProfit` (retorno bruto, sin DD/estabilidad) | Ranking premia curvas frágiles / overfit |
| 2 | WFA/MonteCarlo/SPP/WhatIf **todos OFF** (solo `RetestWithHigherPrecision`) | Sin gate OOS → 24/24 fallan OOS |
| 3 | Rango corto: BTCUSDT 1h `2026.02.26→2026.8.4` (~5.2 meses) | Muestra insuficiente, sin generalización |
| 4 | `spread=0` + slippage bajo + comisión 0.05% | Fricción irreal → HFT fantasma |
| 5 | Sin filtros de sesión (Londres/NY) ni de régimen (ATR/ADX) | Opera en regímenes sin edge |
