# ULTRARENTABLE — DIRECT MAINTENANCE DOCTRINE

## 1. Repository authority

The canonical source is:

`JOSFER78/ultrarentable` → `main`

ChatGPT is the direct maintainer, auditor and repair authority for this repository in this workflow.

No external coding orchestrator, watcher or automatic phase dispatcher is required.

## 2. Scientific doctrine

```text
ZERO-MOCK
ZERO-SIMULATION
ZERO-FORCING
ZERO-LOOKAHEAD
REAL-ONLY
EVIDENCE-GATED
```

No fabricated datasets, trades, hashes, metrics, equity curves, balances, fills, certifications or successful states.

Missing evidence must remain explicit:

`NO_EVIDENCE / BLOCKED / UNAVAILABLE / ENGINE_ERROR`

## 3. Direct execution model

For each repair block ChatGPT:

1. reads the real repository state;
2. audits code and architecture;
3. identifies root causes;
4. edits the repository directly when appropriate;
5. adds or repairs tests;
6. uses CI/VPS execution when runtime verification is required;
7. inspects the resulting evidence;
8. only then selects the next repair block.

There is no requirement for another AI agent to implement the work.

## 4. Current priority — Strategy Lab first

Before FONDEO, prop-firm rules, meta-strategies or live execution, ULTRARENTABLE must establish a trustworthy strategy-production chain:


The `/estrategias` page is the primary user surface for this pipeline.

### Hard rule

An extracted strategy is **not** a backtested strategy.
A backtested strategy is **not** a robust strategy.
A robust strategy is **not** automatically certified.

## 5. Strategy extraction rules

Every extracted strategy must preserve, when actually supplied by the source:

- source engine;
- project;
- databank;
- source strategy name;
- raw source statistics;
- canonical source hash;
- explicit symbol/timeframe;
- explicit dataset identity/hash if available.

Missing values remain missing. No default symbol, timeframe, capital, dataset or profitability metric may be injected.

## 6. Organic improvement rules

Strategy improvement is hypothesis-driven, not target-driven.

A mutation requires:

- a proven parent strategy hash;
- a documented failure mode or research hypothesis;
- one bounded change or a clearly accounted mutation bundle;
- a new child hash;
- a new trial id;
- a fresh canonical backtest;
- untouched blind OOS used only for final evaluation;
- explicit lineage from parent to child.

Never mutate parameters repeatedly until a desired ROI appears without accounting for the trials.

Never rewrite historical evidence to improve a result.

## 7. Quantitative result identity

Every quantitative result must identify, where applicable:

```text
strategy_id
strategy_version
strategy_hash
dataset_id
data_hash
engine_version
execution_policy_version
validation_run_id
ledger_hash
evidence_bundle_id
code_commit_sha
```

A new strategy/engine/data/policy version invalidates affected old evidence until revalidated.

## 8. Discovery

Discovery must optimize the research process, not merely maximize a backtest number.

Preserve:

- Strategy Genome;
- behavioral clustering and diversity;
- trial accounting;
- campaigns;
- discovery score separate from certification;
- exploration/exploitation;
- research budgets;
- fertility;
- blind OOS / blind research;
- robustness and execution stress.

## 9. ULTRA

ULTRA is registry-driven. No hard-coded crypto list or timeframe list is the scientific boundary.

`+1000%` is a research objective, never a forced acceptance criterion.

Extreme convexity, asymmetric payoff, aggressive exploration and independent risk budgets are allowed only when represented explicitly in the strategy/risk contract and tested with real execution assumptions.

## 10. FONDEO

`TRACK_FONDEO = FUTURES ONLY`.

No Forex spot/CFD or crypto perpetual enters Fondeo research or certification.

Evaluation and funded-account risk policies are separate and must be resolved by firm/product/account/date policy data.
