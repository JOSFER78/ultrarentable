## Mission
Establish one deterministic, versioned, hashable canonical representation of a strategy and prove that the execution engine consumes that exact representation without semantic drift, hidden defaults, duplicated rules or silent transformations.

The goal is infrastructure integrity, NOT producing attractive returns.

## Mandatory work

### P02-001-01 — Canonical Strategy Contract
Audit and, if necessary, implement the canonical strategy schema covering at minimum:
- strategy_id
- strategy_version
- strategy_hash
- instrument/timeframe references
- entry logic
- exit logic
- position/risk instructions
- execution semantics
- required parameters
- schema/policy versions

No duplicated authoritative strategy definition may exist in frontend, backend, tests or adapters.

### P02-001-02 — Deterministic Serialization / Hashing
Prove that identical canonical strategy bytes produce identical hashes and that any material semantic change produces a different version/hash. No synthetic hashes.

### P02-001-03 — Runtime Consumption
Trace the real path from canonical strategy artifact to compiler/runtime/execution. Prove that runtime consumes the canonical object and cannot silently substitute defaults, aliases, parameters or rules.

### P02-001-04 — Fail-Closed Validation
Invalid, incomplete, incompatible or ambiguous strategy definitions must be rejected before quantitative execution. No fallback strategy, random parameter, missing-value fabrication or permissive coercion.

### P02-001-05 — Lineage / Version Governance
Every execution must be able to identify the exact strategy, engine, execution policy and dataset identity used. A new material strategy version cannot inherit certification from its parent.

### P02-001-06 — Determinism Tests
Using real repository components, demonstrate deterministic results for the same canonical strategy + dataset + execution policy. Test mutation/version/hash invariants and rejection of malformed definitions.

### P02-001-07 — API/UI Provenance
If strategy data is exposed to API/UI, verify it is read from the canonical source and displays version/hash/status from evidence. UI must not calculate or invent quantitative truth.

### P02-001-08 — Red-Team
Search for hardcoded strategy defaults, duplicate models, silent coercions, random/seed shortcuts, mock execution, lookahead, hidden parameter overrides and any route that bypasses the canonical contract.
